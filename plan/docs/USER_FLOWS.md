# User flows v0.1

## 1. Онбординг взрослого
1. `Welcome` → «Я родитель» → email/password → email verification.
2. Экран согласия: правила, политика конфиденциальности, отдельно необходимые согласия/уведомления на обработку данных ребёнка; логировать версию и время.
3. «Создать семью» → имя семьи (optional) → «Добавить ребёнка» (имя/псевдоним, возрастная группа).
4. «Подключить устройство ребёнка»: показать шестизначный одноразовый код, время действия, инструкцию.
5. Взрослый открывает ленту и может создать задание.

**Ошибки:** неподтверждённый email, повторный email, слабый пароль, истекшая ссылка, отмена согласия.

## 2. Подключение ребёнка
1. На отдельном смартфоне `Welcome` → «Я ребёнок» → экран `6 цифр`.
2. POST `/v1/auth/child/pair`: одноразовый код + device public identifier. Проверка rate-limit, кода, времени, числа попыток.
3. При верном коде создаётся запрос `pending` на привязку конкретного устройства; код атомарно погашается. Ребёнок видит «Ожидаем подтверждения родителя».
4. Родитель подтверждает запрос на своём устройстве; только после этого child получает защищённую сессию и ленту. При отказе сессия не создаётся.
5. Родитель может отключить устройство/выдать новый код; при отказе/утрате сессии нужна новая авторизация через код.

**Ошибки:** 5 неверных попыток → временная блокировка; код истёк/использован; чужой аккаунт/подозрительная смена телефона.

## 3. Задание
`adult creates` → occurrence `open` → ребёнок добавляет обязательные фото(1–3) и описание → occurrence `submitted` → взрослому приходит уведомление → `approve` (очередь баллов начислена, occurrence `completed`) **или** `request_changes` (occurrence `open`, хранится feedback, ребёнку push) → новый отчёт.

**Случаи:** повторное нажатие approve, одновременное approve двух взрослых, повторное расписание, дедлайн, нулевые баллы, нет связи при загрузке фото, файл недоступен, удалённый аккаунт.

## 4. Недельный дневник
Создать предметы → недельный шаблон (пн–вс, номер урока) → открыть дату → урок → ввести ДЗ, заметку, замечание → добавить оценку `1..5`. Child может создать оценку только один раз для данного события API (idempotency key); повторно — отдельная оценка, если нужно. Parent может откорректировать/мягко удалить существующую с записью истории. Переход по аналитике открывает список составляющих оценок.

## 5. Магазин
Взрослый создаёт товар «Поиграть 1 час» (например, 50 баллов) → ребёнок видит стоимость и баланс → нажимает «Запросить» → резерв/списание 50 баллов → родитель подтверждает или отклоняет → при отклонении 50 баллов возвращаются → при подтверждении родитель отдельно отмечает исполнение.

**Ошибки:** недостаточно баллов, item скрыт после просмотра, повторные запросы, параллельное списание, отказ после одобрения, ребёнок вышел из семьи.

## 6. Настроение и разговор
В выбранное вечернее время ребёнок получает ненавязчивый запрос → 1–10 + эмодзи + опциональный комментарий → отправить → в БД одна отметка за дату → родители с разрешением получают нейтральный push о факте отметки → родитель открывает график и число → отдельное регулярное напоминание «Поговорите с ребёнком о его дне» **без сводок**.

**Обязательное:** комментарий ребёнка не должен попасть в parent JSON, push, логи, crash reports или аналитические события. Отсутствие отметки не трактуется как плохое настроение.

## 7. Желания
Ребёнок создаёт `title` (+ `description, image, product_link` по желанию) → взрослый видит карточку и может `fulfilled` → ребёнок видит изменение. Связь с магазином **нет**. Переход по товарной ссылке у ребёнка заблокирован/защитный gate до отдельного решения.

## 8. Другие члены семьи
Owner отправляет приглашение конкретному email → приглашённый создаёт/входит во взрослый аккаунт → owner выбирает `relation_label` и `permission_profile` → helper создаёт доступное ему задание → ребёнок видит «от Бабушки» → владельцу доступны отзыв права и аудит.

## 9. Удаление / отзыв
Owner может отозвать ребёнку доступ с конкретного устройства, удалить/деактивировать family member, запросить удаление семейных данных. Любая операция пересчитывает scopes и инвалидирует токены. Правовой статус данных других членов семьи и сроки удаления должен определить legal reviewer.
