# Журнал решений и TBD

## Подтверждено пользователем (D)
- D01: дети 7–12 лет; D02: несколько взрослых и детей; D03: одно приложение; D04: email/password для взрослых и шестизначный код для детей.
- D05: дневник реальный по структуре (предметы/уроки/ДЗ/оценки/замечания), записи могут вносить обе стороны, **оценки ребёнку нельзя править и удалять**, родителю можно.
- D06: задачи разовые/повторяющиеся; обязательно фото+описание; взрослый одобряет либо возвращает с инструкцией.
- D07: баллы и магазин родительских наград; желания не связаны автоматически с магазином.
- D08: настроение 1–10 + эмодзи + необязательный комментарий; вечер, пуш о факте отметки; взрослому график и оценка, **не ИИ-анализ**.
- D09: напоминание о разговоре без сводок; D10: главная — лента дня; D11: международный рынок (privacy-first), RU+EN, бесплатно; D12: доп. функции позже; D13: проектировать полностью до этапной реализации.

## Предложенные архитектурные допущения (P) — технические дефолты, не подтверждены отдельно
- P01: React Native/Expo; serverless API на Vercel; Supabase (PostgreSQL + RLS + private Storage); без Bubble.
- P02: PIN — одноразовый pairing code на 10 минут с 5 попытками и ограничением частоты, не постоянный пароль; после его ввода родитель подтверждает запрос привязки нового устройства (pending approval). По умолчанию одно активное устройство ребёнка, можно перепривязать.
- P03: семейные разрешения `owner`, `co_parent`, `helper`; родство — отдельный отображаемый атрибут. Helper по умолчанию управляет своими заданиями, но не читает настроение/оценки без назначения более высоких прав.
- P04: владелец и co_parent видят оценки настроения, не текст комментария; helper не имеет доступа к настроению.
- P05: оценки ребёнка сохраняются с источником; взрослые правят с аудитом; ребёнок может править ДЗ и заметки, но не существующие оценки.
- P06: магазин: резервирование баллов сразу при заказе, возврат при отказе; реальных денег нет.
- P07: напоминания ребёнку в 20:00, взрослому о разговоре в 20:30 (по локальной timezone семьи; при онбординге спрашивать/определять по устройству). Отметка настроения не обязательна и не штрафуется.
- P08: «достижение» MVP — ручная запись с временным стандартным значком; расширенная коллекция TBD.
- P09: ребёнок может редактировать свою вечернюю отметку в тот же локальный день, уведомление отправляется один раз за дату.
- P10: нет внешних ссылок для детей без контроля; ссылки из списка желаний полноценно открываются взрослым.
- P11: никакой автоматической оценки эмоциональных рисков до отдельного safety-проектирования.
- P12: юридическая проверка для целевых рынков (GDPR/COPPA/локальные требования), согласий и роли data controller перед публичным запуском; регион хранения Supabase зафиксировать ADR-ом до prod.

Если P01–P12 меняются, агент обновляет этот файл, архитектуру, SQL, API и тесты **в одной PR**.

## Юридические/эксплуатационные вопросы до production
- Законность обработки данных детей и согласия представителей; возраст/права старшего брата или сестры.
- Категория App Store (Kids Category или не Kids), доступ к внешним ссылкам, политика фото, отсутствие рекламных SDK.
- Договоры с провайдерами и трансграничные передачи при пушах, сборках, диагностике, резервном копировании.
- Политика сроков хранения и удаления семейных данных, контроль оснований для доступа других взрослых.
- Конкретная почтовая служба, регионы данных Vercel/Supabase (data residency) для целевых рынков, условия DPA-обработки.
